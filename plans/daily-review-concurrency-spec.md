## 问题陈述（Problem Statement）

日常整理的集中审核中，用户难以判断整批分析推进到哪里、当前文章为何长时间没有建议，以及任务是否已停止。首页偏向最终归档结果，审核页偏向建议和选择数量，缺少统一的分析进度。

目前文章之间、篇内分段及摘要归并主要串行，长文需要连续等待多次模型响应；中途失败还可能重复处理已经成功的分段。单纯增加文件并发或段并发容易使两层数量相乘，突破用户愿意承担的请求压力。

本规格改善日常集中审核的处理效率、进度可见性和失败续跑，同时保留全文覆盖、人工审核及归档安全边界。

## 解决方案（Solution）

不同文章与同一文章的独立分段可同时分析，所有模型请求共享同一整理器服务内的最大并发数，默认 3。汇总、分类和重试也占用该额度；系统按前置结果是否就绪派发请求，跨文章分配机会并优先推进接近形成完整建议的工作。

每篇完成后立即显示可审核建议。首页与集中审核页使用一致的阶段和数量口径，主进度为已产出完整审核建议的文章数量，同时展示篇内阶段、分段进度、实际模型并发占用、请求完成数量和耗时。分析完成、等待人工审核与归档完成明确区分。

用户可以边分析边修改、勾选和保存审核。暂停后不再派发新请求，等待在途请求结束并保存结果；分析结束或安全暂停后才允许归档。失败和重启后可复用有效的成功分段，原文、模型或分析规则变化时复核结果有效性。

第一版保持既有切段规则、提示词语义和模型分析步骤。主要收益是缩短等待、减少失败后的重复工作，不承诺减少正常成功路径的模型调用数或固定倍数的提速。

## 用户故事（User Stories）

1. 作为日常整理使用者，我希望多篇文章同时推进，以便不必等待前一篇的完整流程结束。
2. 作为长文整理使用者，我希望同一文章的独立分段同时分析，以便缩短全文分析等待。
3. 作为使用者，我希望独立的同轮摘要汇总也能并发，以便分段完成后不出现不必要的串行等待。
4. 作为使用者，我希望汇总与分类等待所需证据齐备，以便并发不牺牲全文覆盖和判断依据。
5. 作为使用者，我希望只设置一个最大模型并发数，以便不必计算文件数与分段数相乘的请求量。
6. 作为多知识库使用者，我希望同一整理器服务的任务共用额度，以便多开任务不会突破上限。
7. 作为首次使用者，我希望默认并发数为 3，以便无需配置即可启动。
8. 作为使用者，我希望并发设置保存在服务端，以便刷新或重启后仍然生效。
9. 作为使用者，我希望运行中调高上限后增加派发，以便利用可用模型容量。
10. 作为使用者，我希望调低上限时保留在途请求并停止超额派发，以便不丢弃已经消耗时间的结果。
11. 作为使用者，我希望看到实际占用与设置上限，以便理解调低后的暂时收敛状态。
12. 作为短文与长文混合整理使用者，我希望文章之间公平获得机会，以便长文不独占请求池。
13. 作为审核者，我希望接近完成的文章优先完成汇总和分类，以便尽早获得完整建议。
14. 作为长文整理使用者，我希望持续有新短文就绪时长文仍能推进，以便不会无限等待。
15. 作为审核者，我希望每篇完成后即可看到完整建议，以便不用等待整批完成。
16. 作为任务查看者，我希望首页和审核页显示相同口径的真实阶段和进度，以便不误把归档成功数当作分析进度。
17. 作为任务查看者，我希望分别看到可审核、处理中、等待、失败及例外材料，以便了解剩余工作。
18. 作为任务查看者，我希望看到当前文章的分段完成量、汇总或分类阶段，以便理解长时间等待发生在哪一步。
19. 作为任务查看者，我希望看到真实请求数量、重试和耗时，以便评估并发效果。
20. 作为使用者，我希望暂停立即停止派发新请求，以便控制后续工作量。
21. 作为使用者，我希望暂停期间保留在途结果并显示剩余请求，以便理解何时能安全操作材料。
22. 作为使用者，我希望继续分析时复用有效结果，以便不重复处理已经完成的分段。
23. 作为遇到短暂网络错误的使用者，我希望系统有限重试并展示状态，以便不必为每次瞬时错误手工操作。
24. 作为遇到限流的使用者，我希望系统等待并降低请求压力，以便不反复产生失败调用。
25. 作为遇到局部失败的使用者，我希望只有所属文章停止新请求，以便其他文章继续完成。
26. 作为遇到局部失败的使用者，我希望所属文章其他在途请求的成功结果仍然保存，以便后续补跑可复用。
27. 作为使用者，我希望公共故障只暂停相同模型配置的任务，以便不阻塞无关任务。
28. 作为使用者，我希望没有可运行工作后明确看到分析结束及失败项，以便任务不会永远显示运行中。
29. 作为使用者，我希望有重试失败项入口，以便故障消除后补齐剩余工作。
30. 作为重启服务的使用者，我希望任务等待手动继续，以便重启不会自动发起模型调用。
31. 作为重启服务的使用者，我希望已持久化的有效结果仍可复用，以便保留此前工作。
32. 作为修改材料的使用者，我希望该篇旧分析失效并重新分析，以便不混用不同版本的原文。
33. 作为切换模型或分析规则的使用者，我希望旧配置的分析结果不被直接复用，以便结果依据一致。
34. 作为仅调整并发数的使用者，我希望分析缓存保持有效，以便调速不会触发重做。
35. 作为审核者，我希望分析期间可修改、勾选和保存已完成材料，以便处理和审核能够交错进行。
36. 作为审核者，我希望后台刷新和迟到结果不覆盖手改内容，以便保留我的判断。
37. 作为审核者，我希望源内容或分类基线变化时撤销相关旧授权并要求重审，以便不会提交过期方案。
38. 作为审核者，我希望归档只在分析结束或安全暂停后放行，以便文件变更不干扰在途分析。
39. 作为审核者，我希望安全暂停后能归档已审核的部分材料，以便无需处理完整批次才取得成果。
40. 作为继续任务的使用者，我希望部分归档后重新核验剩余分类基线，以便目录变化不会沿用旧建议。
41. 作为继续任务的使用者，我希望分类变化仅重做受影响分类，以便正文未变时保留已有正文分析。
42. 作为同一知识库的使用者，我希望分析和归档有明确执行互斥，以便不同批次不争用同一份材料。
43. 作为使用者，我希望离开审核页后任务仍在本地服务后台推进，以便页面生命周期不控制分析生命周期。
44. 作为使用者，我希望材料不足以形成可靠建议时仍列为例外，以便并发不会把失败或低信息材料算成正常建议。

## 实现决策（Implementation Decisions）

### 范围与服务级并发额度

- 面向日常整理集中审核；复用后台作业、内容规划、模型调用、批次持久化、审核失效与公开批次视图的现有职责边界。
- 最大并发数作用于同一个整理器服务实例，不承诺跨独立进程或跨设备配额。服务内模型出口共用额度，不能由另一路调用绕过限制；共享接入不改变首次重构本身的产品流程。
- 分段分析、摘要归并、分类检索和选择、实际重试及证据修复请求都计入额度。排队、等待退避、文件读取、持久化及页面刷新不占用模型请求位置。
- Codex CLI 路径中的一次整理器调用按一个在途调用占位，直到该调用结束；不能将此统计宣称为 CLI 内部网络请求数、token 或费用。
- 默认上限为 3，通过经现有会话保护的服务端读写能力配置并持久化，输入必须为合法正整数；不支持的值明确拒绝，不能静默变为无限并发。
- 调高后允许立即补充派发；调低不取消在途调用，占用未低于新上限前不得启动下一请求。页面明确展示收敛状态。
- 同一知识库一次只运行一个批次的分析或归档；不同知识库共享额度并可同时分析。分析执行权不能阻止该批次对已完成材料进行合法审核保存。

### 依赖、调度与并发保存

- 调度单位为依赖已满足的模型请求，同时允许跨文件及篇内并发。同一轮独立汇总可并行；后续汇总、分类必须等待其依赖的成功结果。
- 结果按原文段序归位，保持既有完整覆盖、汇总分组和证据校验语义，禁止以响应到达顺序改变内容次序。
- 在文章之间轮流提供机会，优先推进接近产出完整建议的汇总和分类；持续就绪的长文工作不能因新短文到达而饥饿。不要求特定队列数据结构。
- 长时间模型请求不得持有阻塞其他独立分析或审核保存的全局状态锁；实际状态变更须按当前版本合并并原子持久化，不能整批回写旧快照覆盖其他完成项或人工编辑。
- 同一逻辑工作不能因重复启动、轮询、继续或重试点击被重复派发。迟到结果必须检查来源、任务版本和分析配置是否仍有效。

### 检查点与继续分析

- 成功分段形成持久化检查点，绑定源文件内容、分段位置及影响分析语义的有效模型配置和分析规则版本。敏感配置不能明文进入进度、报告或检查点展示。
- 源文变化使该篇旧分析失效；模型或分析规则变化时不复用旧配置结果；调整并发上限不使结果失效。旧版缓存不能证明有效时保守重算，既有审核与执行记录不得损坏。
- 已确认落盘的有效成功分段在重试或重启后复用。进程退出时尚未确认完成的请求可以重新执行，不承诺远端请求恰好执行一次或免除重复费用。
- 服务重启后恢复中断状态，不自动派发请求，用户继续后先检查结果有效性。
- 部分归档后继续，已归档材料不再参与待分析队列；剩余材料重新核验来源和分类基线。仅分类变化时复用正文分析，重做受影响分类并使相关审核失效。

### 暂停、失败与完成状态

- 暂停从当前材料边界细化为请求边界：接收暂停后停止派发新的分段、汇总、分类及重试，已发出请求结束并保存后才进入已暂停。
- 在途请求仍受正常超时机制约束，不以无限等待维持正在暂停。已暂停后归档仍须满足原有审核、外部写入暂停和历史验证条件。
- 暂时网络错误采用有限重试；限流等待并降低派发压力，不忙循环重试。具体次数、退避参数与错误分类在实现中集中定义并可测试，不由本规格虚构供应商容量。
- 局部请求重试耗尽后停止所属文章的新请求，保留该篇其他在途成功结果，其他文章继续。用户可针对失败项重新启动未完成工作。
- 鉴权或额度等明确公共故障暂停同一模型配置的相关任务；其他配置继续。暂停应包含尚在排队的受影响工作，恢复不能形成无界重试循环。
- 没有可运行工作且没有在途请求后必须进入明确结束状态；存在失败时显示结束及失败项，不将其误标为全部成功或继续运行。
- 低信息、无法可靠分类、人工保留及分析失败按各自真实原因列为例外或终止结果，不能伪装成可审核材料。

### 进度与审核交互

- 公开视图支持多个同时处理的文章，不能继续仅用一个当前材料字段表达全部工作。保留兼容读取或提供明确兼容迁移。
- 区分文章状态、模型请求状态与归档结果：主进度为产出完整审核建议的材料数，另显示处理中、等待、失败和例外，不能把分段完成当成整篇完成，也不能用归档成功数替代分析进度。
- 篇内显示当前阶段、已完成及总分段数；汇总或分类阶段显示可确定的工作量，不能展示虚假的全局百分比或预计剩余时间。
- 全局显示设置上限和实际占用；任务侧展示该批次请求完成量、成功及失败/重试信息与处理耗时。统计应覆盖所有实际发起的请求阶段，不能沿用只统计分段数量的字段作为总调用数。
- 耗时口径需明确：排队、执行与等待人工审核不混为一个模型耗时；暂停和重启时间不冒充持续模型运行。历史不可恢复的在途计量可标为未知，不得伪造精确数值。
- 结果完成即发布到审核界面，首页和审核页口径一致。用户聚焦输入框时仍可更新独立进度区域，但不得覆盖输入、打断焦点或清除跨页选择。
- 保存已完成材料的审核与后台分析可以并行，操作只影响目标材料和其必要依赖。基线失效时明确撤销过期选择与执行授权并要求重审，人工草稿不得悄悄变成有效授权。
- 归档在分析结束或安全暂停后放行；在途或正在暂停时服务端同样拒绝，而非仅禁用按钮。未选中、失败和例外材料遵循现有保留规则。
- 页面进度和设置接入现有界面体系；本规格定义数据与行为，页面整体视觉与布局遵循独立的界面改版规格，不另造布局方案。

## 测试决策（Testing Decisions）

用户已于 2026-10-05 确认本节测试边界并授权发布。本节规定实现阶段的验收，不代表本轮已运行测试。

### 主要测试边界

优先使用现有公开 HTTP 批次接口，从创建、启动、读取、审核保存、暂停、继续和归档操作验证可观察行为。复用现有模型生成依赖注入，以可控制完成顺序、失败类型和请求阻塞的替身驱动真实调度与持久化，不替换调度器本身。

现有后台作业测试已覆盖真实子进程、脱离页面运行、重复启动、知识库互斥和中断恢复；内容规划测试覆盖全文证据与缓存；集中审核测试覆盖人工编辑、跨页选择和失效处理。扩展这些现有入口与合成知识库夹具，页面交互补充独立进度刷新、焦点和草稿保护，不新增仅供测试调用的业务接口。

好测试检查公开结果、模型出口的实际重叠及次数、持久化续跑行为和必要文件结果，不断言内部队列类、私有函数顺序、对象布局或 CSS 类名。模拟模型出口是观测外部调用的边界，不是对实现结构的约束。

### 必须覆盖的验收场景

1. 同一文章多个独立分段及不同文章确实重叠执行；同一服务跨知识库总占用始终受固定上限约束。
2. 同轮独立摘要汇总可重叠，依赖不全时不执行后续汇总或分类；乱序返回仍按原文位置覆盖全部内容且没有遗漏、重复或串篇。
3. 分段、汇总、分类、重试及证据修复共用额度；不同模型配置也不能突破服务总上限；API 与 CLI 适配路径均不绕过限制。
4. 重复启动与并发继续不重复派发；同一知识库第二批次无法同时分析或归档，但当前批次的合法审核保存可进行。
5. 运行中提高上限能够增加派发，降低后不取消在途且无新增超额请求；刷新及重启保留设置，非法设置被拒绝。
6. 长短文混合时各篇有推进机会，完成建议持续可见；持续就绪的长文不被无限推迟。
7. 暂停后无新请求，在途结果保存，归零后才可归档；暂停期间到期的重试不能绕过暂停，超时或失败不会永久卡住暂停状态。
8. 局部重试耗尽只停止所属文章的新工作，其他文章继续；同篇在途成功结果保留，最终显示分析结束及失败项。
9. 限流产生退避并降低压力；鉴权或额度公共故障暂停同配置任务，独立配置继续；无界自动重试不存在。
10. 真实服务进程在部分分段落盘后中断，重启不触发模型；手动继续复用成功分段，只补齐未完成或失效工作。
11. 原文、模型和规则变化分别使相应旧分析失效；只调并发不失效；旧版缓存不能证明兼容时不会被冒用。
12. 异步旧结果晚于基线变化或人工审核返回时，不能覆盖新结果、人工名称、分类或选择，也不能恢复已撤销的执行授权。
13. 页面边分析边编辑、筛选、分页和保存，草稿、焦点及跨页选择受保护，独立进度仍更新；可审核数与失败、例外、归档数不混淆。
14. 安全暂停后部分归档再继续，已归档材料不重复处理，正文未变的剩余材料保留分析；分类变化只使受影响分类和审核失效。
15. 首页与审核页一致显示分析运行、正在暂停、已暂停、中断、失败结束、待审核及归档结果；离开页面不终止后台任务。
16. 在相同合成输入与可控模型延迟下对照串行和并发：验证请求重叠及总耗时改善，同时正常成功路径的调用数、全文覆盖和依赖关系保持一致，不以脆弱的固定毫秒阈值作为唯一正确性依据。
17. 回归既有命名、分类证据校验、纯新增归档、历史验证与恢复边界；共享模型出口接入后首次重构行为兼容。

真实浏览器核对运行中进度、多篇处理明细、动态上限、输入期间刷新、暂停和失败结束状态。合成模型测试证明调度和恢复正确性，不等于真实供应商提速；真实模型成本或性能验证须独立报告。实现完成后运行相关测试与仓库要求的全量检查，明确已有基线改动或失败带来的限制。

## 范围外（Out of Scope）

- 重新设计首次整体重构、分类树提议和归并的产品流程；仅保证共享基础设施兼容。
- 改变切段策略、缩减全文覆盖、重写分析提示词、合并分析与分类请求、改用向量检索或其他减少正常调用数的算法。
- 承诺固定提速倍数、精确预计剩余时间、真实 token/费用计量或 CLI 内部网络调用统计。
- 跨进程、跨设备的分布式配额和任务协调。
- 强制终止在途远端调用，保证远端恰好一次执行或退款。
- 绕过已有分类、审核、来源变化、外部写入暂停、备份、验证与恢复规则。
- 在分析请求仍在途时执行归档，或自动恢复服务重启后的模型调用。
- 本次规格阶段修改业务代码、提交推送 Git、运行真实材料或付费模型。
- 重做页面视觉体系；独立界面改版规格继续负责整体布局与视觉验收。
