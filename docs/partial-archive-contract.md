# 部分归档与分类依赖复核

日常整理安全暂停或结束后，仅对本次明确选择且仍有效的材料执行既有归档。分析在运行或正在暂停时，同库后台执行权阻止所有直接归档入口；在途结果保存、执行权归还后才允许归档。外部写入暂停、来源身份、重名、关联、历史验证、目录依赖和恢复现场的保护继续适用。成功归档项不会再进入分析；未选及失败项保留原处，稳定归档请求重复提交仅查询已有结果。

`continueAnalysis` 未另给 `sourceIds` 时复用此前处理记录的明确范围，不把原先未选材料加入处理。若此前未限定范围，则继续原有整份记录范围。成功正文检查点仍按来源哈希和分析版本复用，正文变化只重分析该篇；分类复核不改变全文检查点版本。

分类结果保存实际读取的依赖快照：普通检索依赖全目录的路径和同义名，最终选择依赖实际考虑的候选元数据；生成新增类别及其复用判断读取完整目录，使用完整目录依赖。未审核建议遇到新增、改名或同义名变化时重新分类；未被模型读取的其他类别说明变化可证明不影响该建议。用户明确审核已有目标后，依赖收窄到目标及其父级元数据，允许无关新增或说明变化保留审核。目标移除、改名、相关说明或元数据变化仍撤授权。旧记录缺少依赖证明时保守重分类。

可证明仍有效时，规划服务与处理记录共同更新当前目录基线，保存前后目录哈希与依赖摘要的证明，重新计算冻结计划签名；并非不经核验改写所有计划。公开 `reviewBasis.catalogHash` 对新结果表示分类依赖摘要，旧结果仍使用目录哈希。无关复核不会误撤有效勾选，相关变化增加审核版本、清除冻结位置与选择，人工名称和可展示草稿保留。新增类别落地使其他未选旧提议失效，不自动延续批准；同次明确授权的共享类别仍沿原有精确提议证明执行。

首次重构仍依赖完整分类树，不收窄为逐篇复核。任何完整原库基线变化仍使整份共享备份、历史验证和迁移执行依据失效；逐篇正文及审核的有效范围不因此扩大为整批正文重跑。

`POST /api/inbox/recheck` 在知识库安全静止时复核所属材料，不启动模型或归档。知识库归档结束后也执行这一复核，公开 `reviewCheck`：本次受影响、仍有效、需要正文分析、需要分类、已审核、已归档与此前续跑范围的文件整理项 ID。公开批次也提供对应来源范围，供归档协调复用。写入中断时返回 `blocked` 及原因，保留已执行结果和日志，只能经原恢复入口处理。复核结果是所示时间的快照，实际写入仍重新核验；自动安全暂停和继续由后续协调切片实现。

公开 HTTP 测试使用真实临时库和可控模型，覆盖候选说明、路径与同义名、人工目标、在途归零、部分归档、检查点复用、正文变化、范围续跑及知识库复核结果；回归完整历史验证、纯新增类别共享与恢复约束。前端延续已归档、待继续和需重审状态，独立显示复核范围，不重建人工编辑节点。
