# 2026-10-11 全页面风格复核

用户反馈：部分打开的页面风格不同，Logo 和图标随意。本轮将验收范围扩展到所有正式页面的公共外壳与控件，保留 B2/B3/B4 主页面的布局和原有业务流程。

## 改动与对照

- 页头统一使用书本标志；导航、任务、材料、目录统一使用本地 SVG，均为 24×24 画布、1.7 描边。移除原先混用的 Unicode 图形与各自手画的文件轮廓。
- 字体、颜色、间距、按钮、输入框、焦点与响应式导航由 `app.css` 共用；报告、恢复、备份与迁移等专用页使用同一个服务器外壳。
- 专用页可以直达设置和分类；批次列表失败不会阻挡这两个入口。任务直达链接仍优先进入对应任务。
- 批量迁移路径和任务报告的表格在窄屏局部滚动，避免全页横向溢出或挤窄路径字段。

原版专用页：[恢复](../screenshots/recovery.jpg)、[兼容检查](../screenshots/preflight.jpg)。新版：[恢复](recovery-desktop.jpg)、[兼容检查](preflight-desktop.jpg)，与[首页](home-desktop.jpg)、[阅读](reading-desktop.jpg)、[分类](categories-desktop.jpg)使用同一套视觉语言。

## 第三轮：设置入口闪回

原服务端总是输出首页首帧，客户端等库请求结束后才根据 `view` 切换设置；加载期间用户已经打开设置时，迟到初始化也可能重新选择首页。

现服务端根据已验证的目标预设标题、导航和加载状态，设置、分类及任务直达首帧不呈现首页；客户端初始化尊重用户之后的导航选择。补充实际 HTTP 首帧与延迟库请求回归，均先红后绿。

实际浏览器从恢复页点击设置、从首页直接点击设置均进入目标视图。另以 2.5 秒延迟的合成库响应核验：[等待加载](settings-loading-no-flash.jpg)只显示设置标题和加载状态，[完成加载](settings-loaded-no-flash.jpg)直接显示真实返回的设置表单。未保存任何真实设置，未调用模型。
复核发现并修复两处边界：未知 `view` 通过显式白名单安全回退；迟到环境只补未编辑字段，保留人工草稿、真实编辑记录身份与显式新增意图。[慢加载草稿保留截图](settings-draft-preserved.jpg)使用合成设置，未保存。相应测试先红后绿，相关 25/25，独立复核 20/20；Standards 与 Spec 遗留均为 0。最终全量与当前提交 CI 结果见 PR #33。

本轮最终 Node v25.9.0 全量：247 项，242 通过、5 跳过、0 失败（86 秒）。跳过项依赖真实 Rust rescan，当前提交 CI 另行覆盖。
