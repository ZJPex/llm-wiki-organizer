# 旧分析结果接入契约与验证（#43）

知识库收件箱扫描发现旧任务结果，服务端核验后接入，不因读取或扫描自动调用模型。原任务记录、检查点、归档日志与恢复现场保持原入口。

## 有效性与身份

- 正文复用核验当前来源物理身份、来源目录、全文哈希、模型语义配置指纹及正文分析规则版本，并确认引用仍出现在原文。分类规则变化不使正文缓存失效。
- 分类与人工授权另行核验实际知识库身份、摄取关联、分类依赖、分类规则版本与冻结授权。知识库身份使用分类规则模块的根目录、项目 ID 和物理目录证明；不覆盖工作区原有毫秒格式身份字段。
- 自动建议核验有效分类规则摘要；人工授权核验完整规则摘要。旧规则摘要缺失仅在当前规则为空时兼容。分类依赖使用 #39 的实际检索、候选说明或人工目标依赖证明；不将无关目录新增扩大成全文重分析。
- 冻结授权还核验计划哈希、源路径与身份、正文哈希、人工名称、分类、标签、目标位置及新增类别接受证明。有效旧人工确认零模型重建当前冻结授权；不能证明授权时仅保存正文及人工草稿，明确要求重审。
- 同一工作区设置 ID 下知识库项目、物理目录或来源目录范围改变会创建新收件箱作用域和审核身份。旧作用域保留历史，页面清除旧选择与编辑节点。

## 公开接口

- `POST /api/inbox/scan`：发现文件、直接复用有效旧结果；多份不同结果显示 `legacy-conflict`，不按更新时间覆盖人工结果。运行中的旧任务显示 `legacy-active`；有未完成写入现场的旧任务显示 `legacy-recovery`，必须从原任务查询或恢复。
- `POST /api/inbox/chooseLegacy`：提交 `{id,itemId,originId}`，仅能选择当前文件展示的来源。重新核验来源，重复同一选择幂等，不启动模型或归档。
- `POST /api/inbox/history`：所属知识库内可读取旧结果来源、验证结论和原报告链接。摘要仅公开固定字段，并隐藏绝对私有路径和当前配置凭据；不公开原始批次、配置或执行记录。
- 已归档旧结果通过原批次建立归档台账，不创建新的归档执行。目标移走或删除后仍保留归档历史，显示可用性，不重新进入待处理队列，也不使整体列表或扫描失败。
- 成功接入结果与收件箱关联分别持久化；关联保存前进程退出后，重新扫描复用同一结果，不增建重复任务。后续继续、失败重试仍按 #37 的明确来源集合进行。

## 自动验证

使用公开 HTTP、真实临时库及持久化状态、可控模型替身和 DOM。旧格式测试只删除历史记录中后来新增的身份及规则证明，不用内部函数直接生成接入结果。

组合重点 `test/legacy-results.test.js` 与 `test/library-inbox-ui.test.js` 共 23 项通过，31.1 秒，覆盖有效与未知身份、模型配置失效、冻结凭据损坏、规则变化、分类依赖变化、明确冲突选择、重复接入、重启、执行现场保留、运行中旧任务、历史摘要、作用域变化、归档删除，以及原有后台刷新和审核草稿保护。最终固定源码完整测试另行记录；真实浏览器与 CI 由父规格组合验收。
