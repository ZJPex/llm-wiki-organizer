# 模型失败隔离与文件重试（#37）

## 重试与隔离契约

`src/model-failure.js` 集中定义错误类别与策略：每个逻辑请求最多尝试 3 次，退避为 250、500 毫秒，服务端 `Retry-After` 可延长等待但上限为 2 秒。退避不占模型请求额度；每次实际尝试重新经过共享调度器。原有证据校验修复仍经过同一出口。

| 错误 | 行为 |
| --- | --- |
| HTTP 408、425、5xx，暂时网络异常 | 有限重试，耗尽后停止所属文章的新请求 |
| HTTP 429 | 有限退避；同配置冷却后先单请求探测，成功后恢复派发 |
| HTTP 401、403 | 停止同有效模型配置的新请求，等待手动恢复 |
| HTTP 402，429 中明确的额度错误代码 | 同配置公共故障，不作限流重试 |
| 响应格式或其他请求错误 | 本篇失败，停止本篇的新请求 |

配置隔离使用分析版本的配置指纹，凭据与自定义请求头仅进入散列计算。公开错误只包含固定中文原因、安全错误代码和尝试次数；服务端响应正文、密钥及端点不进入公开状态。不同配置继续使用服务的共享额度。

本篇失败仍等待已发出的请求结束，并保留成功检查点；其他文章继续推进。没有本次可运行工作且在途归零时保存终态，不自动无限重试。手动重试复用有效检查点，未确认的远端请求仍允许重新执行。

## 按文件恢复范围

`startAnalysis` / `continueAnalysis` 可携带 `sourceIds`，必须是该收件箱批次的非空、无重复文件集合；缺省代表用户明确继续全部当前未完成工作。收件箱 `start(itemIds)` 始终把所选文件映射成对应集合。

公开和持久化的 `analysisJob.sourceIds` 保存本次范围，`null` 表示全部当前队列。后续归档协调恢复已有运行范围时应复用此字段，不能扩大到其他失败文件。

所选工作结束而其他文件仍有缺口时状态为 `partial`，允许手动 `continueAnalysis`。状态不是“全部成功”，且不再占用知识库分析执行权。

`source.failure` 包含 `code/message/attempts/scope`，`scope` 为 `article` 或 `model`；`source.progress.retry` 在退避或重试中包含有限尝试与等待信息。失败文件不计为可审核建议。页面展示影响范围、原因和“重试此文件”，其实际请求范围与按钮一致。

## 验证边界

公开 Organizer HTTP、真实临时状态与真实本地 HTTP 模型服务；覆盖 429、401、明确额度错误、503 耗尽、单篇队列停止、成功检查点复用、重复继续、暂停与到期重试竞争，以及只重试所选文件。DOM 验证退避、影响范围与单文件恢复动作。最终真实浏览器由集成验收统一执行。
