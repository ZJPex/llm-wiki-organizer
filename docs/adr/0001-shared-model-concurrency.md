# 日常整理共享模型并发额度并隔离归档写入

日常集中审核允许不同源文件及同一源文件的独立分段并发处理；同一整理器服务内的任务共享一个模型请求并发上限，分段分析、摘要汇总与分类请求均计入，避免文件级与分段级限额相乘或多开任务突破额度。调度在文章之间轮流分配机会，并优先推进接近形成完整审核建议的汇总和分类，同时保障长文持续推进。

分析期间允许查看、修改、勾选和保存已完成材料的审核结果，后台不得覆盖人工修改；归档须等待整批分析结束或安全暂停，以避免文件和目录变更影响在途分析。暂停停止派发新请求，等待已发出的请求结束并保存结果，不承诺立即取消远端请求或免除费用。

同一知识库一次只运行一个批次的分析或归档，不同知识库可共享额度同时分析。公共故障按模型配置隔离；服务重启不自动恢复调用。原文与分析配置未变的成功结果可复用，部分归档后的续跑仍须复核分类基线，避免旧分类审核被重新用于写入。

这些是 2026-10-04 两轮讨论确认的目标行为，尚未实现；首次整体重构的流程优化不在本次范围。第一版保留原有全文分析步骤，优先改善并发、可见进度及失败续跑，减少正常路径调用次数另行评估。完整产品与恢复边界见 [设计讨论](../../plans/daily-review-concurrency.md)。

## 2026-10-11：知识库内按文件处理与归档协调

用户已确认日常整理改为知识库内持续存在的收件箱，以文件为处理单位，允许处理中追加文件；不再要求创建或选择批次任务。为避免持续追加使已审核材料一直无法归档，用户归档已确认文件时，系统停止当前知识库的新分析派发，等待在途结果保存后归档，复核分类变化对剩余建议的影响，再继续处理。

此决定更新上述按批次组织日常操作及手动暂停归档的方式，仍保留同一知识库内分析与归档隔离、全局模型额度、人工修改保护和有效结果复用；服务重启后仍需用户手动继续。它是已确认的目标行为，不表示业务实现已完成。详见[本轮讨论](../../plans/inbox-classification-discussion-2026-10-11.md)。
