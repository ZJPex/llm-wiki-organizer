# 知识库分类偏好

保存审核默认只修改当前文件。用户明确勾选“将本次分类偏好保存为本知识库的后续规则”，填写适用主题及范围后，收件箱审核请求才提交 `saveClassificationRule:true` 与 `ruleText`。规则最多一千字，只能指向当前已存在且经过审核的主分类；空字符串仍表示合法的 Raw 根类别。尚未落地的新类别须先确认归档，不能把规则保存当成创建授权。

规则独立持久化在规划状态目录，绑定规范化知识库位置、项目标识及保留精度的物理目录身份。同一服务中的其他知识库不继承规则；相同位置替换项目后，旧设置须重新核对，重新保存设置也不会续用旧规则。重新进入与服务重启读取规则，不自动启动模型或迁移历史材料。公共收件箱列表返回 `classificationRules` 及 `rulesHash`；页面可查看已保存规则。

后续分类的检索与候选选择请求携带 `classificationRules`。规则是偏好参考，不能取代正文证据与可靠主归属判断。目标类别已失效的规则不进入模型请求；模型输出仍须通过既有类别路径、精确证据及不确定状态校验。规则产生的建议保持待审核，没有归档、创建目录或历史迁移授权。

分类结果与文件冻结计划绑定独立的 `rulesHash`。规则变化使未执行的旧分类需重新检索与审核，保留可靠正文分析及已确认名称，不更改全文 `analysisVersion`。在途分类末尾再次核验规则版本；迟到的旧规则建议不能覆盖新版本。准备归档及执行前继续核验冻结规则版本，失败保留来源和证据。审核草稿同时沿用公共 `reviewBasis`，分类版本变化不能转化成旧草稿对新依据的授权。

公开 HTTP 验证覆盖默认不推广、显式规则、连续新材料、同服务真实两库、重启、同位置替换项目、旧分类复核仅复用正文、失效类别过滤及证据不足；DOM 验证显式选择、规则输入与草稿刷新。模型边界使用可控替身，不请求真实模型。
