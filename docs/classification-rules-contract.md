# 知识库分类偏好

保存审核默认只修改当前文件。用户明确勾选“将本次分类偏好保存为本知识库的后续规则”，填写适用主题及范围后，收件箱审核请求才提交 `saveClassificationRule:true` 与 `ruleText`。规则最多一千字，只能指向当前已存在或明确接受的新类别主分类；空字符串仍表示合法的 Raw 根类别。未落地的新类别记录为待生效规则，规则保存不创建目录、不授予归档权限。

规则独立持久化在规划状态目录，绑定规范化知识库位置、项目标识及保留精度的物理目录身份。同一服务中的其他知识库不继承规则；相同位置替换项目后，旧设置须重新核对，重新保存设置也不会续用旧规则。重新进入与服务重启读取规则，不自动启动模型或迁移历史材料。公共收件箱列表返回 `classificationRules` 及 `rulesHash`；页面可查看已保存规则。

没有项目配置的旧独立规划入口仍可分类，身份返回空值、规则为空，保存后续规则则拒绝。已捕获真实身份的任务不会通过项目配置缺失降级复用旧审核。冻结计划另保存状态目录与身份，持久归档入口不依赖模型服务也能独立核验规则；规则位置必须位于来源和知识库之外。

后续分类的检索与候选选择请求携带 `classificationRules`。规则是偏好参考，不能取代正文证据与可靠主归属判断。目标类别已失效的规则不进入模型请求；模型输出仍须通过既有类别路径、精确证据及不确定状态校验。规则产生的建议保持待审核，没有归档、创建目录或历史迁移授权。

新类别待生效规则绑定经过审核的 `newCategoryHash` 与所属库身份。目录未存在时状态为 `waiting-category`；实际目录的 `.category.json.organizerProposalHash` 与提议匹配后状态为 `active`，才参与分类。目录被同名其他提议占用时状态为 `category-mismatch`，不会只凭路径续用规则。类别目录快照包含该提议证明，证明变化也使旧分类基线失效。页面列出这些规则状态，待生效偏好随重启保留，用户仍须明确确认归档才能落地类别。

分类结果与文件冻结计划绑定独立的 `rulesHash`。规则变化使未执行的旧分类需重新检索与审核，保留可靠正文分析及已确认名称，不更改全文 `analysisVersion`。在途分类末尾再次核验规则版本；迟到的旧规则建议不能覆盖新版本。准备归档及执行前继续核验冻结规则版本，失败保留来源和证据。审核草稿同时沿用公共 `reviewBasis`，分类版本变化不能转化成旧草稿对新依据的授权。

`rulesHash` 表示持久偏好记录，`effectiveRulesHash` 则只摘要实际可进入模型的有效规则集合，包含库身份、目标路径及提议证明。待生效规则激活、目标失效或提议证明变化，即使原记录没改，也会改变有效摘要。自动分类、公开审核依据与迟到结果都核验它；旧自动建议仅重做分类，保留正文。明确人工确认的冻结目标以目录依赖证明核验，本次已授权新类别创建后规则生效不会撤销同次所选材料的归档授权，也不会续权未选材料。

公开 HTTP 验证覆盖默认不推广、显式规则、连续新材料、同服务真实两库、重启、同位置替换项目、旧分类复核仅复用正文、失效类别过滤及证据不足；DOM 验证显式选择、规则输入与草稿刷新。模型边界使用可控替身，不请求真实模型。

首轮全量暴露旧独立分类缺少项目配置、已有直接归档入口缺少规划服务参数两项兼容问题，修复后旧分类、发现与归档回归共 30 项通过；合入模型故障恢复后，规则、DOM 与归档重点回归 32 项通过。最终集成版本的验证证据见[任务验收记录](verification/inbox-41/classification-rules-46.md)。
