# 分析期间保存审核

日常整理的模型等待与人工审核使用不同执行边界。同一知识库继续分析时，可对已经完成正文与分类建议的文件整理项保存名称、主分类、主题标签和选择，包括此前完成的处理记录。审核以最新持久记录中的材料为单位提交，不取得归档执行权，不等待其他材料的模型响应。首次重构仍沿用整体分类树审核约束。

文件整理项与批次材料公开 `reviewBasis`，包含正文哈希、当前位置、审核版本与分类目录哈希及新增分类提议摘要。`POST /api/inbox/review` 必须带回用户所见的依据；缺失返回 `REVIEW_REQUIRED`，陈旧依据返回 `STALE_REVIEW`。批次审核接口仍支持原有严格 `revision`；提供每项 `reviewBasis` 时，只有进度更新造成的整批版本变化不阻挡保存。保存会增加材料审核版本，旧草稿不能再次绑定已改变的审核。外部正文或目录变化仍触发实际基线复核，撤销相关选择、冻结位置和执行授权，保留已确认文件名。

新版收件箱的卡片编辑区保持稳定，状态和进度独立更新。旧集中审核页面在聚焦编辑时继续读取进度并保留当前阅读项，即使该项因基线变化不再符合筛选；筛选、分页及跨页选择仍按原有操作范围计算。手改名称和分类草稿可以继续展示，但失效时明确提示重审并清除选择；重新明确选择后才能按当前依据保存。成功的本次审核保存保留用户选择。

旧页面提供独立的“保存所选审核”操作。分析正在运行或正在暂停时，两套页面均禁止归档，服务端所有直接归档入口仍核验同库分析执行权。暂停须等待在途调用和保存完成；审核保存不会移动、删除或复制原文件。后续归档协调切片可在这一边界上组织安全暂停与续跑。

公开 HTTP 测试使用真实临时知识库与可控模型响应，覆盖交错写回、跨处理记录审核、暂停期归档阻断、缺失及陈旧依据、正文变化撤销授权。DOM 测试覆盖输入节点、焦点、光标、持续进度、筛选与失效草稿；最终真实浏览器验收由父规格统一执行。
